## 3. What this wave learned — new named classes, read before writing proofs

- **`awk -v` processes escape sequences; ENVIRON does not.** A mutation literal ending in a lone
  backslash (`--verbose \`) passed through `-v` is kept by BSD awk (local green) and mangled by
  mawk/gawk (CI red: T-mutation-verbose-flag "MIS-TARGETED" on a correct hook). Pass literals to
  awk via `ENVIRON`, always; `-v` only for numbers. The one-commit CI round on #293 is the repro.
- **Commit GREEN before running a checkout-restore mutation battery.** `git checkout -- <file>`
  restores from HEAD; run before the GREEN commit exists, every "restore" reverts the fix itself
  and the battery's failures go noisy in ways that LOOK like bad mutants. The tell: mutants
  failing MORE cases than their design predicts. (Caught live this wave by exactly that tell.)
- **A reviewer's surviving mutant is a case you owe, and the fix is its own verification.** Three
  reviewer mutants survived rounds this wave — the `^`-drop (killed by T-stub-anchor-indent + the
  canary's C5 lockstep assertion), the stream-source swap (killed by T-stub-warn-on-stdout — the
  BL-193 stream-routing lesson made this one real, not theoretical), and the digest/named-tag
  re-pin (killed by the deny-by-default sweep). Each kill was verified by re-applying the exact
  mutant and watching exactly the new case fail.
- **`perl -pi` with a `\s*$` anchor eats the trailing newline** and joins the next line into the
  replacement — 22 templates were briefly broken this way and the anchored test caught it. Use
  `[ \t]*\n$` and emit the `\n` explicitly.
- **The CLAUDE.md multibyte-adjacent-expansion trap fired live** (`$repin` + em-dash under
  `set -u`, bash 3.2): the documented trap list is not decorative.
- **`gh pr checks --watch`'s exit code is not a verdict.** It exited 0 over a run whose required
  aggregator was FAIL (#293 round 1). Verify every check state explicitly (`gh pr checks` +
  `mergeStateStatus`) before any merge decision.
- **The shard-cap doctrine worked as designed — obey it, don't override it.** BL-200's detector
  suite pushed the sast shard from ~4m46 to ~6m31 typical, and a slow-registry evening then
  busted the 12-minute cap mid-run (this handoff PR's own round 1: job canceled during bl132,
  `pysemgrep` still alive at the kill — a timeout, not a test failure). The cap's comment says
  approaching it is the RE-PIN signal, not a raise-the-limit signal: the detector suite moved to
  the `rest` complement (semgrep is in every shard per BL-190), the canary stayed beside the
  sast toolchain.
- **Measured facts beat entry prose.** Two build-time measurements changed the BL-200 design: the
  prefilter fact (semgrep only parses files some rule's literal admits — it is why the canary can
  be network-free AND why the detector covers exactly the threat model), and `--verbose` leaving
  stdout byte-identical with the banner still exactly-once (without which the whole approach was
  a regression). Measure before building on an entry's description of a tool.
